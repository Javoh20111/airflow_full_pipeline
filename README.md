# PROJECT REQUIREMENTS 
**Objective:** Build a reliable and scalable **Apache Airflow pipeline** that automates the end-to-end data lifecycle, from scraping fresh data and ingesting it into the data warehouse to transforming and serving analytics-ready data to downstream users.  
  
**Overview:**
This project automates and combines two earlier efforts — *Tashkent Apartment Analysis* (Python-based EDA and data cleaning) and *DataWarehouse* (a PostgreSQL medallion-architecture warehouse) — into a single scheduled Airflow pipeline that scrapes, transforms, validates, and loads apartment listing data end-to-end.
  
**Scope:**
- **Source:** CSV files generated by a custom web scraper, with each row representing an individual apartment listing.
- **Data ingestion:** Airflow triggers the scraper and loads the resulting raw CSV data into the data platform (Bronze layer).
- **Data transformation:** Airflow orchestrates the transformation and cleaning of raw data into structured, analytics-ready datasets (Silver layer).
- **Data validation:** Automated checks are performed to ensure data quality, schema consistency, and successful pipeline execution at each layer.
- **Pipeline orchestration:** Apache Airflow manages task dependencies, execution order, and scheduling across the entire pipeline.
- **Data serving:** The processed data is made available in the analytics/serving layer for downstream SQL queries, dashboards, and analysis.
- **Single source:** The pipeline currently processes apartment listing data from one scraper; integration with additional sources or external systems is outside the scope.
- **Latest-data approach:** Each run replaces prior data with the latest scraped snapshot; historical dataset versioning is outside the current scope.
- **Documentation:** The pipeline, data flow, and key datasets are documented clearly enough for analysts and business stakeholders to understand and use the resulting data independently.
